# Порядок публикации Zlatopil Alert

Этот документ фиксирует схему канала обновлений. Пакеты и стабильные манифесты публикуются только после сборки и проверки на соответствующих Windows.

## Структура канала

В ветке `main` размещаются два отдельных стабильных манифеста:

- `stable/win7/manifest.json` — пакет для Windows 7 SP1.
- `stable/win10/manifest.json` — пакет для Windows 10.

Публичные HTTPS-адреса:

- `https://raw.githubusercontent.com/usznuas/zlatopil-alert-updates/main/stable/win7/manifest.json`
- `https://raw.githubusercontent.com/usznuas/zlatopil-alert-updates/main/stable/win10/manifest.json`

Приложение выбирает адрес по целевому каналу сборки. Поле `platform` обязательно и должно совпадать с каналом приложения.

## Формат подписываемого сообщения

Для совместимости скрипт `Sign-ReleaseManifest.ps1` и проверяющий код приложения подписывают UTF-8 payload без завершающего перевода строки:

`ZLATOPIL_ALERT|version|platform|packageUrl|sha256|releaseNotes`

Где:
- `version` — версия вида `0.5.0`;
- `platform` — строго `win7` или `win10`;
- `packageUrl` — HTTPS-ссылка на установочный пакет;
- `sha256` — 64 шестнадцатеричных символа в верхнем регистре;
- `releaseNotes` — текст примечаний к выпуску.

JSON-манифест содержит поля `product` (= `ZlatopilAlert`), `version`, `platform`, `packageUrl`, `sha256`, `signature` (Base64 RSA/SHA-256) и `releaseNotes`.

## Публикация релиза

Планируемый тег первого глобального выпуска: `v0.5.0`.

После отдельной сборки и тестирования подготавливаются два установочных пакета — Win7 и Win10. Каждый пакет получает SHA-256. Затем создаётся отдельный подписанный манифест для соответствующего канала.

Проверка установщика и отката на реальных системах обязательна до публикации манифестов как стабильных. Пока приложение выполняет только проверку доступности и подписи манифеста; загрузка и установка обновления из интерфейса ещё не входят в текущую сборку-кандидат.

## Подписание и ключи

Для подписи используется `Sign-ReleaseManifest.ps1` и локальный закрытый RSA-3072 ключ.

Закрытый ключ:
- хранится у владельца офлайн, желательно на зашифрованном носителе и с отдельной резервной копией;
- не загружается в этот репозиторий, GitHub Releases, исходники или пакеты программы;
- не отправляется в чат и не включается в диагностические отчёты.

Открытый ключ закреплён в исходном коде приложения. Перед первой публикацией требуется выполнить тестовую подпись и проверить её именно встроенным механизмом приложения.

## Текущий статус

Публичный репозиторий и документация канала готовы. Настоящие пакеты, манифесты и релиз ещё не опубликованы. Первый планируемый стабильный выпуск — глобальная версия 0.5.0 после проверки.
